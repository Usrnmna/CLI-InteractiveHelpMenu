## Listing keywords

- **Address.** The menu includes all address flag tests and their inverses. `temporary` and `secondary` test one kernel bit with different IPv6 and IPv4 meanings. `primary` inverts that bit. `dynamic` inverts `permanent`. The flag table also accepts less prominent selectors such as `optimistic`, `stable-privacy` and `mngtmpaddr`. The latter selects a template used to create temporary addresses. The listing can select by master, VRF, group or link kind. On Resolute, `proto` takes a numeric byte and also admits addresses whose kernel response lacks a protocol attribute. The name-or-number grammar presented alongside address creation in the synopsis overstates the listing parser. [Address parser](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/ip/ipaddress.c?h=v6.19.0)
- **Link.** `down` tests the administrative UP bit. `novf` suppresses the kernel request for SR-IOV virtual-function details while leaving eligible devices in the listing. Both apply to link output in the address listing too. Noble lacks both spellings and treats an unknown lone word in that position as a device name. `vrf NAME` selects members of that existing VRF device. The parser accepts a bare device name after `show`; `help [TYPE]` can print a particular link kind's usage. Link listing uses the link-layer family and skips the address dump. Address flag, prefix and protocol tests therefore belong to the address menu. [Link dispatch](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/ip/iplink.c?h=v7.3.0) · [Shared listing parser](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/ip/ipaddress.c?h=v7.3.0)
- **Route.** `to` and `from` allow `root`, `match` and `exact`. A destination selector can omit `to`. The `from` selector compares the route's source prefix, and the manual describes its use with cloned routes. `src` tests the route's preferred source address. `oif` is the outgoing `dev` selector and `iif` selects the incoming interface. `cached`, `cloned` and `table cache` request cloned routes. On modern kernels the IPv4 route cache is empty. `tos` and `dsfield` read numeric bytes in hexadecimal, even without a prefix. `metric`, `priority` and `preference` accept an unsigned route priority. The word `low` does not supply that numeric operand. `realms FROM/TO` accepts two realm names or IDs, or a raw numeric field. `realm TO` selects a destination realm, and `realms FROM/` selects a source realm. Both spellings enter the same parser branch and accept the two-sided form. [Route listing parser](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/ip/iproute.c?h=v7.3.0) · [Realm parsing](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/ip/rtm_map.c?h=v7.3.0) · [DS-field and realm names](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/lib/rt_names.c?h=v7.3.0)

## Socket options and exceptions

- **Output and selection.** The expanded menu covers protocol and address families, timer and memory fields, TCP information, TIPC fields, BPF filters and storage, security contexts, summaries and events. It distinguishes a port expression from a table list or state selector. The `--kill` row describes the effect on live sockets, the IPv4/IPv6 restriction and the kernel's handling of unsupported sockets. The `--net=` row accepts an existing named network namespace. The `--query=` row includes group and table names. The parser's `all` table group omits TIPC, which can be added explicitly. [Socket option and table parser](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/misc/ss.c?h=v7.3.0)
- **Raw diagnostics.** The manual describes a filtered TCP dump. The implementation opens the destination in write mode and takes its raw-dump branch before parsing the positional expression or filter file. The client applies supported TCP/state selection, but a port expression does not restrict the binary dump. Both Ubuntu packages wrote data with a deliberately invalid expression that failed in normal display mode. [Noble dump path](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/misc/ss.c?h=v6.1.0) · [Resolute dump path](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/misc/ss.c?h=v6.19.0)
- **Threads.** Both manuals describe `-T` as implying process output. Noble showed the fixture process with `-T` alone. Resolute suppressed the ownership column until `-p` was supplied. `-pT` showed the process on both. The newer source disables the column when the process flag is clear. Context fields additionally depend on active SELinux and access to the relevant process. [Resolute column selection](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/misc/ss.c?h=v6.19.0)
- **Availability.** Resolute adds `-Q/--no-queues`, `-B/--bound-inactive` and the two build-dependent BPF socket-storage switches. A specific map ID must resolve to an accessible map. The all-maps and individual-ID requests are mutually exclusive. Both Ubuntu releases accept `-d/--dccp` and the `dccp` table name. Upstream 7.3 removes DCCP selection. A residual long-option declaration has no implementing switch case. The lowercase `-v` version alias works in all three tagged sources although fixed help lists uppercase `-V`. Kernel protocol support and an installed client's compiled features determine which data can actually be returned. [Noble options](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/misc/ss.c?h=v6.1.0) · [Resolute options](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/misc/ss.c?h=v6.19.0) · [Upstream options](https://git.kernel.org/pub/scm/network/iproute2/iproute2.git/tree/misc/ss.c?h=v7.3.0)

## Syntax outside these menus

The parent `ip` accepts family, namespace, output-format, detail and statistics options before the object. The separate address modification, flush, save, showdump and restore operations own address creation flags, lifetimes and peer/broadcast data. Link creation, set, deletion, property, xstats and afstats own their device-specific parameters. Route mutation, lookup and dump/restore operations own nexthops, encapsulations, transport lookup ports and per-route metrics. Shared words such as `master`, `dev`, `type` and `metric` retain their **listing** meanings here. Bare device names, prefixes and optional multiword selectors are typed as operands. The editor can resume after its declared single operand; more complex native forms such as `via inet6 ADDRESS` are explained in Details and can be typed literally.

The `ss` positional filter has its own state and expression grammar, including boolean operators, host and port predicates, interface, cgroup and mark tests. These words and family-specific addresses are expression operands. The `stop_at_positional` boundary keeps ordinary option insertion ahead of that expression. Timer types, memory keys, TCP field names, kernel state names and BPF map contents are data or output fields. They remain available in the manuals without becoming insertable options.
