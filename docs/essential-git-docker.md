## Fixed sources and independent comparison

The Git driver requests only the leaf manual. The two Docker engine routes request both `docker help run` or `docker help image ls` and the corresponding manual. Compose requests `docker compose LEAF --help`. The manual argv is `man -P /bin/cat --no-hyphenation --no-justification -s 1:8 -- PAGE`. Probes used the discovery locale and 100-column manual width. The source manifest abbreviates this argv as `man PAGE`. Each new packaged capture comes from an offline sandbox with a private home, the release's extracted amd64 packages and no Docker daemon. Ubuntu package archive SHA-256 values were checked before extraction. The minimized Noble image's `man` prints its installation placeholder. The Noble manual captures therefore use its actual packaged pages rendered with the host sandbox's man-db 2.13.1. Noble's Docker executable and Compose plugin also ran directly in the Noble sandbox. The Docker fixed responses match the Resolute builds byte for byte. [Discovery route and process policy](discovery-and-safety.md)

## Material corrections and boundaries

* Git's unified diff context has two distinct contracts. In log, show and diff, bare `-U` or `--unified` uses the default. An explicit count attaches to the option, as in `-U0` or `--unified=0`. Resolute commit requires a count, and Noble commit does not declare these switches. The tagged diff parser specifies optional arity. The earlier isolated commit checks established the separate commit behavior and the hook-precedence correction. [Git 2.43 diff parser](https://raw.githubusercontent.com/git/git/v2.43.0/diff.c) · [Git 2.53 diff parser](https://raw.githubusercontent.com/git/git/v2.53.0/diff.c) · [Packaged Git behavioral evidence](git-commit-log-manual-coverage.md)
* The Ubuntu Docker manual still describes an effective kernel memory limit. Docker 29.1.3 registers `--kernel-memory` against a temporary compatibility variable and marks it deprecated. It accepts a value and does not apply a limit. The menu qualifies this observed release and preserves the older manual explanation in Details. Boolean examples such as `--detach=true|false` and `--rm true|false` no longer turn a bare flag into a required value. All 102 terms and aliases in docker-run's OPTIONS section retain their declared descriptions. [Docker CLI v29.1.3 flag registration](https://raw.githubusercontent.com/docker/cli/v29.1.3/cli/command/container/opts.go)
* The editable Git/Docker spellings come from their identified sources. Remote or repository names, paths, image names, Compose services, child-command switches, numeric placeholders, patch contents, old examples and parent globals outside leaf help stay outside the selectable inventory. The full manual can mention additional accepted options in prose. Such mentions alone do not establish a separate declaration. Compose's tagged config handler accepts a comma-separated service list or `*` for `--hash`; fixed help only supplies a string operand. [Compose config handler](https://raw.githubusercontent.com/docker/compose/v2.40.3/cmd/compose/config.go) · [Compose exec parsing boundary](https://raw.githubusercontent.com/docker/compose/v2.40.3/cmd/compose/exec.go) · [Compose run parsing boundary](https://raw.githubusercontent.com/docker/compose/v2.40.3/cmd/compose/run.go)

## Verification

The visible Git summaries now lead with each option’s effect where its source opens with background. For example, `--allow-empty` permits a commit with the same tree as its parent, and `-l` limits exhaustive rename/copy detection. The original qualifications remain in Details.

The four family regressions compare complete historical declarations and optionality, reject prose-derived rows, check first-sentence reflow against the source and compare both packaged Git releases and every Docker path against the complete inventories. These passive tests passed 4/0/0 on each target. Unittest took 0.445 s on Ubuntu 26.04.1/Python 3.14.4, 0.918 s on Ubuntu 24.04.5/Python 3.10.20 and 0.521 s on Ubuntu 24.04.5/Python 3.12.3. The terminal checks and full compatibility suites are recorded separately in the shared Essential verification report linked from the roadmap.
