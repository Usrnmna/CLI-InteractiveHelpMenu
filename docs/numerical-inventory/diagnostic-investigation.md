## Confirmed review corrections and bounded source findings

**Fixed digit actions and counts.** The former universal level/enumeration
classification was inappropriate for fifteen external identities:

- `du -0`, `fd -0`, `fdfind -0`, `psql -0` and `yq eval -0` select NUL output;
  `psql -1` wraps the supplied command sequence in a transaction;
  `scp -3` selects transfer through the local host. These seven are actions.
- `fd -1` and `fdfind -1` limit results to one. `fzf -0` exits for no initial-query
  match and `fzf -1` selects the only initial-query match. These four concern
  counted matches/results, rather than physical units or ordered levels.
- The three `git stash show` digit observations and `sftp -1` retain unresolved
  command context, as described below.

References are the [coreutils 9.4 manual](https://raw.githubusercontent.com/coreutils/coreutils/v9.4/doc/coreutils.texi),
[fd 9.0.0 source](https://raw.githubusercontent.com/sharkdp/fd/v9.0.0/src/cli.rs),
[fzf 0.44.1 manual](https://raw.githubusercontent.com/junegunn/fzf/0.44.1/man/man1/fzf.1),
[PostgreSQL 16.15 psql reference](https://raw.githubusercontent.com/postgres/postgres/REL_16_15/doc/src/sgml/ref/psql-ref.sgml),
[yq 4.54.1 declaration](https://raw.githubusercontent.com/mikefarah/yq/v4.54.1/cmd/root.go)
and [OpenSSH 9.6p1 scp manual](https://raw.githubusercontent.com/openssh/openssh-portable/V_9_6_P1/scp.1).
The scp capture has no exact release; agreement with that reference does not
authenticate its version. The seven retained gzip/OpenSSL/ss selectors are
triaged from capture wording only, with a fresh authoritative audit still open.

**Shared GNU numerical prose.** `sort -k` and `--key=KEYDEF` occur in the same
explicit declaration, so the short spelling now receives the same composite
planning classification. No relationship is inferred from matching summaries.
The 9.4 manual defines one-based field/character positions and a special zero
end-character position. `sort -S` bare values use 1024-byte units; `%` refers to
physical memory. Block-size prefixes distinguish decimal and binary scales.
Head/tail byte counts and line counts remain different subjects even when their
multiplier syntax is shared. Head negative counts omit trailing items; tail
`+NUM` begins at a one-based position. `du --threshold` also has apparent-size
and inode modes, so its preserved `SIZE` prose is not a universal byte contract.
The applicable source sections are **Block size**, **sort invocation**,
**du invocation**, **head invocation**, **tail invocation** and
`multiplierSuffixes` in the
[9.4 manual source](https://raw.githubusercontent.com/coreutils/coreutils/v9.4/doc/coreutils.texi).

**Other count subjects.** The ten observations concern directory levels,
commits, parallel fetch children, merge inputs, concurrent sorts, unchanged
polling iterations and worker threads. `du` root depth is zero; tail's unchanged
polling count is not itself a duration; xz zero requests automatic thread
selection within resource limits. Coreutils 9.4, the
[Git 2.43 fetch options](https://raw.githubusercontent.com/git/git/v2.43.0/Documentation/fetch-options.txt)
and [xz 5.4.5 manual](https://raw.githubusercontent.com/tukaani-project/xz/v5.4.5/src/xz/xz.1)
support the bounded subject comparisons. Complete bounds, signed parsing and
resource-dependent behavior are not newly certified.

**Time and version evidence.** Tail and Compose captures name seconds. The
[Compose 2.40.3 declaration](https://raw.githubusercontent.com/docker/compose/v2.40.3/cmd/compose/down.go)
converts an explicitly changed integer timeout to seconds; absence delegates
timeout choice rather than universally selecting the CLI parser's literal zero.
The [pip 24.0 declaration](https://raw.githubusercontent.com/pypa/pip/24.0/src/pip/_internal/cli/cmdoptions.py)
uses a floating socket timeout with default 15 seconds, matching the separate
selected-python module capture. The root pip specimen says only `Set timeout`
with `<sec>` and has no version. Its previous group explanation overstated the
prose evidence; that explanation is corrected without rewriting the specimen
or promoting its driver arity declaration.

**VLC scale remains unresolved.** The unversioned synthetic specimen supplies
`--volume <integer [0 .. 512]>` and `--rate <float>`. In
[VLC 3.0.21 source](https://raw.githubusercontent.com/videolan/vlc/3.0.21/src/libvlc-module.c),
nominal playback rate is 1.0, while the integer `volume` option is marked
obsolete since 2.1.0. Neither modern playback/gain meaning nor a percentage
scale can be assigned to the specimen without identifying its intended
historical implementation. Both observations remain source-derived/unresolved.
