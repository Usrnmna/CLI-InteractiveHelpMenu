## Existing rows and additions

- **Shared options.** The original account, configuration, project, quiet and verbosity summaries gave their basic effects. Details now explain per-invocation overrides, defaults for suppressed prompts, and separate resource and quota projects. The new rows expose access-token files, billing projects, flag files, flattening, both forms of help, impersonation, HTTP logging, tracing, output suppression and its inverse, and the quiet alias. `--version` and `-v` belong to the root version action. The GA menus exclude alpha, beta and preview command variants.
- **Config.** All seven original rows remain. `--all` was incomplete. It can include unset properties for a whole configuration or a `SECTION/` operand, while a specific `SECTION/PROPERTY` conflicts. Core properties can omit their section. The missing list controls are `--filter`, `--sort-by` and `--limit`. Config list explicitly removes page-size and URI flags from its parser. [Config profile](../profiles/gcloud-config-list.json)
- **Compute.** All twelve original rows remain. The page-size summary incorrectly called the operand a page count. It bounds resources in each API page. `--limit` caps final output after flattening, sorting and filtering. Service pagination may occur on either side of the filter and limit. `--zones` restricts the zones queried. Filter execution can involve the client, the service or both. The added `--regexp` and `-r` are deprecated whole-name matches. Details explain the replacement `--filter` expression and URI formatting. [Compute profile](../profiles/gcloud-compute-instances-list.json) · [Filter semantics](https://docs.cloud.google.com/sdk/gcloud/reference/topic/filters)
- **Storage.** All fifteen original rows remain. The bucket, recursive and long-output rows needed more than their previous summaries. Quote wildcard URLs for the CLI and use a separate `**` path segment for matches across levels. The recursive flag prints headings for directories. A bucket URL normally lists contents, while `--buckets` lists the bucket. `--full`, `--json` and `--long` are mutually exclusive. The existing `--format` restriction to `gsutil` was accurate. The separate new JSON switch writes metadata. New rows also cover headers, ETags, exhaustive paging, encrypted-object hashes, object-context filters, page tokens, stdin URLs, soft deletion, decryption keys and aliases. `--metadata-filter` applies server-side to objects only. Buckets and folders can still appear. List-command `--filter`, `--limit` and `--page-size` do not appear on this leaf. [Storage profile](../profiles/gcloud-storage-ls.json) · [Storage wildcards](https://docs.cloud.google.com/storage/docs/wildcards)

## Offline parser observations

A separate [version-pinned 590.0.1 SDK archive](https://dl.google.com/dl/cloudsdk/channels/rapid/downloads/google-cloud-cli-590.0.1-linux-x86_64.tar.gz) supplied the parser source and help client. Its SHA-256 was `d1ae7be7e12c4e7d8286fab4774f5441020aca89dc7793ddacbace8d11d20f06`. This is a separate artifact from the historical unversioned download.

The global reference's delegation example reverses the target and delegate roles in its final sentence. In the pinned SDK, `lib/googlecloudsdk/core/credentials/store.py` returns the final email as the target and earlier emails as delegates. The isolated `ParseImpersonationAccounts` function returned `('target', ['delegate-a', 'delegate-b'])` for `delegate-a, delegate-b, target`. The three menus describe this order. No account lookup or token exchange was needed.

With a private home and configuration in an offline namespace, `gcloud FLAG config list --help` produced full leaf help for each of the five new value-taking globals (`--access-token-file`, `--billing-project`, `--flags-file`, `--flatten`, `--trace-token`) and three switches (`--log-http`, `--user-output-enabled`, `--no-user-output-enabled`). Placing `-h` or `--help` first changed which help was printed. The driver recognizes the eight nonterminal additions before the leaf. The focused regression checks that a global operand resembling another command still resolves correctly.
