## Source and release evidence

**pip.** The Noble package is `python3-pip 24.0+dfsg-1ubuntu1.3`. Its `pip(1)` page still identifies the documented release as 1.5.6, dated 2014-06-03. Only 14 spellings appear in GENERAL OPTIONS. INSTALL OPTIONS and UNINSTALL OPTIONS have explicit child owners. The page adds `--log-file` to the fixed root help. The old manual describes a failure-only, non-appending log. The 24.0 CLI declares it as an alias for the verbose appending `--log`. Details now identify both releases. Noble has no separate pip-install or pip-download page in the reviewed package. [Noble pip manual](https://manpages.ubuntu.com/manpages/noble/en/man1/pip.1.html) · [pip 24.0 option definitions](https://github.com/pypa/pip/blob/24.0/src/pip/_internal/cli/cmdoptions.py)

Resolute supplies `python3-pip 25.1.1+dfsg-1ubuntu2`. Its three manuals add explanations and environment-variable names to literal help declarations. Resolute help adds `--resume-retries` on all four paths and `--group` to install and download. Noble's help still advertises `--no-python-version-warning`. Both spellings of the executable were probed separately using the installed Resolute package and a privately extracted Noble package. [Resolute pip manual](https://manpages.ubuntu.com/manpages/resolute/en/man1/pip.1.html) · [Resolute install manual](https://manpages.ubuntu.com/manpages/resolute/en/man1/pip-install.1.html) · [Resolute download manual](https://manpages.ubuntu.com/manpages/resolute/en/man1/pip-download.1.html) · [Upstream pip install](https://pip.pypa.io/en/stable/cli/pip_install/) · [Upstream pip download](https://pip.pypa.io/en/stable/cli/pip_download/)

**npm.** Both releases package npm 9.2.0. The package revisions are `9.2.0~ds1-2` for Noble and `9.2.0~ds3-1` for Resolute. The install and run-script command source files compared byte-identically. The three roff pages differed only in the title date. Full fixed help was captured from the Resolute binary. For install it supplies 30 literals, including five omitted from the WSL excerpt. The manual's bullet definitions independently establish eleven spellings, including four missing short forms. Its prose also mentions global configuration, such as the tag used to select dependencies. Examples, inline mentions and the command aliases in the help footer do not independently declare insertable options. On these packaged pages the Configuration sections reference separate config documentation. When an observed bracketed declaration still lacks prose after merging, its summary and qualifications come from the tagged 9.2.0 configuration. Details identify that release and retain the local syntax. For example, `npm run --ignore-scripts` still runs the requested script and suppresses its pre- and post-scripts. **uv.** The two complete responses came from the upstream Linux x86-64 uv 0.13.1 binary. Its archive SHA-256 matched the checksum published with the release. Its expanded help lists the literal aliases and then documents their values, defaults, environment and interactions in indented paragraphs. For example, the dots in `-q, --quiet...` mark repetition. They consume no argument. The previously missing Details explain how repeating the option suppresses stdout. `uv pip install --no-binary` takes a value, whereas the same spelling on `uv run` is a switch. No suite-specific `uv(1)` page was available on either Ubuntu release. **pnpm.** The upstream pnpm 9.15.9 Linux x64 release embeds Node.js 20.11.1. The complete output contains repeated declarations for `--package-import-method`, `--reporter` and `--filter`. Each displayed syntax now stays beside its own explanation. All three options take one value. `-s` and `--silent` are complete synonyms for `--reporter silent` and consume no value. A selector such as `<pattern>^...` has distinct meaning from `<pattern>...`. The release's typed configuration declares `global-dir` as a string even though the fixed help omits its operand. That correction is limited to the identified version. The WSL excerpt cuts the CI default's explanation mid-sentence. The complete response supplies the remaining explanation. No `pnpm(1)` page was available for either Ubuntu release. ## Reproduction and verification

The complete help and rendered manual files retain the source wording at 100 columns with plain output in the C locale. XZ compression is lossless. Only the private home in npm root help and the probe directory printed by pnpm are replaced by placeholders. Ubuntu page names correspond to the driver's section 1/8 lookup. The Noble pip manual was rendered from the archived suite page. The live menu makes no online documentation request. The tagged npm explanations supplement rows declared by the local synopsis. Both historical Ubuntu 24.04 WSL captures and compact matrix specimens remain unchanged. [Complete response files](../tests/fixtures/essential/package-sources) · [Driver declarations](../config/drivers.example)

The complete inventories were derived from the declaration columns and alias groups in these fixed responses, independently of the discovery parser. For npm, the manual-only short aliases are counted once after merging with help. For pip and uv, declarations belonging to a different command or an indented example were excluded. pnpm aliases and value alternatives were checked against its tagged types. The [focused regressions](../tests/test_essential_packages.py) compare every expected spelling and operand count to the generated rows, and independently check material Details. All six focused tests passed with zero failures and zero skips on Ubuntu 26.04.1/Python 3.14.4 (0.280 s), Ubuntu 24.04.5/Python 3.10.20 (0.582 s) and Ubuntu 24.04.5/Python 3.12.3 (0.320 s). These are parser and generated-profile checks. The shared Essential verification records the terminal and full-suite runs.
