# FFmpeg library options

An FFmpeg option can belong to the executable, a library shared by many components, or a particular codec, container or protocol. For example, `-id3v2_version 3` belongs before an MP3 output filename. It requests an ID3v2.3 header from the MP3 muxer. The same option has no general meaning for video encoders. [Upstream AVOption examples](https://ffmpeg.org/ffmpeg.html#AVOptions) · [Tagged MP3 muxer](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/mp3enc.c)

## Parser, aliases and operand boundaries

1. Native option lookup has priority. The fallback searches the codec class and its registered children, then the format class and its children, including applicable protocols and devices. An unqualified spelling can reach both dictionaries. Codec options permit a stream specifier after a colon. A qualified codec spelling no longer matches an unqualified format name.
2. The scaler and resampler are searched in that order when neither codec nor format lookup has consumed the spelling. Thus `-flags` reaches the codec. Use `-swr_flags` to set audio resampling flags. The generic codec option also takes precedence over the scaler's `threads` field. The scaler explicitly rejects direct `-srcw`, `-srch`, `-dstw`, `-dsth`, `-src_format` and `-dst_format`. Use the CLI size or pixel-format option or a scale filter where appropriate.
3. The legacy codec-only fallback can strip an initial `v`, `a` or `s` and look up a generic codec field. The manual deprecates this syntax. Use `-threads:a` to identify audio explicitly. A registered name takes precedence, as happens with `-ab`. Private codec names and open-ended specifier combinations require checking their own grammar.
4. Every direct AVOption consumes one following shell word, including a boolean. Use `0` or `1` for the boolean value. Automatic selection is available only where the declaration permits it. Named flag values, filter options inside a graph, bitstream-filter arguments and option values read by a component have separate owners.

The three tagged fallback implementations and the operand manual describe this routing. [6.1.1 parser](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n6.1.1/fftools/cmdutils.c) · [8.0.1 parser](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n8.0.1/fftools/cmdutils.c) · [9.1 parser](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/fftools/cmdutils.c) · [9.1 AVOption manual](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/fftools-common-opts.texi)

Library class enumeration using `av_opt_next` and `av_opt_child_class_iterate` identified 38 pairs of directly accessible spellings sharing the same field, type and constant namespace on at least one owner. Twenty-five pairs share the entire set of owners wherever both spellings are present in the three baseline builds. Thirteen pairs have additional meanings elsewhere. For example, `-osr` and `-out_sample_rate` both set the resampler output rate in hertz. The libvpx encoder's `-cpu-used` and `-speed` share a field, while an optical input device uses `-speed` to choose the drive speed. Similarly, an optional AMF encoder gives `-latency` a separate encoding meaning from SRT's `-tsbpddelay`. Both spellings remain searchable and selectable. ## Conditional codecs and manual discrepancies

The [tagged codec inventory](../tests/fixtures/ffmpeg/av-codec-source.tsv) records 184 additional candidate names, their source files, applicable tags, operand types and available manual sections. It compares the codec and conversion-library declarations in 6.1.1, 8.0.1 and 9.1 with the baseline help and native option tables. There are 163 additional directly applicable names. Each requires its registered component and any SDK feature that enables the declaration. The tagged encoder and decoder manuals cover only a subset of wrapper-private settings. Examples include `-afterburner` for FDK AAC, `-max_nal_size` for OpenH264 and `-font` for ARIB subtitles. Thirty-nine already selectable names also carry qualifications for alternative optional codec owners. The inventory provides source-level registration evidence for unavailable codecs. [Encoder manual](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/encoders.texi) · [Decoder manual](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/decoders.texi) · [FDK AAC encoder](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/libfdk-aacenc.c) · [OpenH264 encoder](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/libopenh264enc.c)

The remaining 21 names have separate owners. Ten are codec API fields whose declarations omit CLI flags or expose a read-only result. `-rc_override_count` is explicitly read-only in 9.1. Four LCEVC settings belong in the `-lcevc-dec-params` dictionary. Two belong to an API subtitle rectangle. The MPEG-4 decoder exports `divx_packed` and `quarter_sample` read-only. The DCT API, AV1 coded-bitstream API and bitstream-filter graph each own one further field. [Codec option flags](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/options_table.h) · [LCEVC dictionary](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/lcevcdec.c) · [Subtitle rectangle class](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/options.c) · [MPEG-4 decoder](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/mpeg4videodec.c)

- The libuavs3d guide names `frame_threads`. Its decoder reads the generic codec thread count. The FFmpeg spelling is `-threads`. VVenC registers `-level` and `-qpa` for settings called `levelidc` and `subopt` in its guide. The guide also describes `bitdepth8`; the two reviewed VVenC registrations contain no such switch. [libuavs3d decoder](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/libuavs3d.c) · [VVenC registration](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/libvvenc.c)
- The xHE-AAC encoder guide calls the interval between random-access points `rap_length`. The 9.1 FDK wrapper registers `-rap_interval`, parses a duration and passes milliseconds to the encoder. The libvpx name `vp8-flags` is per-frame metadata. The CLI option `-vp8flags` has its own registration. The x264 and libvpx documentation also uses `nr`; the registered FFmpeg names are `-noise_reduction` and `-noise-sensitivity`, respectively. [xHE-AAC wrapper](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/libfdk-xhe-aacenc.c) · [libvpx wrapper](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/libvpxenc.c) · [x264 wrapper](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/libx264.c)
- Some library fields are results available to a calling application. The HTTP classes in the Ubuntu builds expose `mime_type`, `http_version`, `icy_metadata_headers`, `icy_metadata_packet` and metadata from the response. A separate optional HTTP backend in 9.1 implements a writable HTTP version setting. Noble full help exposes `ts_packetsize` as read-only. The Resolute and 9.1 MPEG-TS classes export `ts_id` and `ts_packetsize` outside their printed help. AC-3 decoder fields `dmix_mode`, `loro_cmixlev`, `loro_surmixlev`, `ltrt_cmixlev` and `ltrt_surmixlev` are read-only there, even when an encoder has a writable field with the same name. The complete captures also flag exported view ID and position arrays read-only. [HTTP protocol declarations](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n8.0.1/libavformat/http.c) · [Optional libcurl protocol](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/libcurl.c) · [MPEG-TS reader](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/mpegts.c) · [AC-3 decoder options](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavcodec/ac3dec_float.c)
- `-resource` and `-location` can reach HTTP option lookup, but the protocol fills them from the requested path and transfer URI. Single-client HTTP resets `reply_code` to 200 and multi-client HTTP requires an application to drive accept and handshake. DTLS's `external_sock` requires an external socket supplied via the API. The inventory records these names as ineffective for the CLI wherever their library class appears. ## Observed parser behavior

A media-free probe of each baseline executable used `-hide_banner -loglevel debug`, the candidate option names with a following value, and `-version`. Each accepted name had to appear in the diagnostic as an AVOption with that argument. The probe matched all 1,168 Noble spellings, 1,186 Resolute spellings and 752 upstream spellings, including the ineffective API settings above. It tested name recognition and argument consumption. It supplied no input or output that could initialize an encoder, open a device or make a connection. In particular, matching a hardware encoder's option establishes no device capability, and recognizing a placeholder `0` does not establish that every component accepts that value. The [media and terminal verification](ffmpeg-manual-coverage.md#verification) records separate checks.

Offline media fixtures on both packaged FFmpeg releases verified three library options on each sandbox target. With a title and MP3 output, `-id3v2_version 3` produced the first five bytes `49 44 33 03 00`; version 4 produced `49 44 33 04 00`. On local input, `-blocksize 32 -i input.mkv` read successfully. A zero block size returned status 222 with an option-setting error from the file protocol, despite its output-only help flag. Two PGM frames at input `-framerate 5/2` produced a stream with an average rate of 5/2 and a duration of 0.800000 seconds according to ffprobe. These media observations are separate from the test-suite counts.
