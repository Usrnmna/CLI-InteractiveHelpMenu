# AI review of the three-level menu plan

**Disposition — Findings incorporated.** This review records the earlier draft. The [updated plan](2026-11-24-menu-detail-levels.md) incorporates the findings and the user's decisions on reclaiming space in Simple and searching for `bps`. The mockups were subsequently approved and implemented. [Rendered results at both sizes](2026-11-24-menu-detail-levels-verification.md)

## First finding — repeated units within one option

The draft shows how two neighboring options can share one note. Open FFmpeg’s `-b:v` by itself and the same problem occurs inside its detail pane. Each suffix form gets its own line with “bits/second,” and the bare-number line gives the unit twice. P3 mentions these forms in its last check, but its grouping rule and mockup cover neighboring options. [Current form rendering](../../../cli_help/value_semantics.py#L841)

Add a single-option Expanded example to P0 and use it as a P3 acceptance check. This proposed excerpt uses a unit heading for the result column and keeps each input’s literal spelling and multiplier visible. The complete screen would include the remaining forms and the encoder qualification.

```text
-b:v BITRATE     Set the target video bitrate

Input suffix     Rate in bits/second for input N
(none)           N
k or K           N × 1,000
Ki               N × 1,024
B                N × 8
```

Check the same selection in the unfiltered list and when it is the only search result. A shared heading inside Expanded remains useful in both cases.

## Decisions for the human reviewer

1. **What changes on screen when the level changes?** The draft makes Detailed and Expanded apply to the selected option. It leaves the surrounding list at one line per entry. That choice keeps nearby flags visible, but the draft also leaves open how much space Simple reserves for a selected pane that may have nothing extra to say. At 80×24 the current list has seven physical rows. Adding spacers to that same space fits only four options, or three with a one-row heading. **Suggested edit:** reclaim unused detail space in Simple. Compare a complete 80×24 screen at each level with the same option selected, including a long flag and the footer. Also compare Simple and Expanded at 60×16 before settling on the layout. [Current pane allocation](../../../cli_help/ui.py#L228)
2. **When is a shared unit note short enough to help?** In FFmpeg’s **Stream codecs** category, filtering on `-b:` returns exactly `-b:v` and `-b:a`. Both use bps for bare numbers. The draft’s heading is 75 cells long. The current option pane allows 53 cells at 80 columns and 39 at 60. **Suggested edit:** use “Bare bitrates use bps (bits/second)” for that filtered pair. Show how the note behaves after clearing the filter, scrolling past the pair, or selecting a single result. Compare the result with local unit labels before choosing how to handle subgroups inside a mixed list. [Option-pane width](../../../cli_help/ui.py#L244) · [FFmpeg rate definitions](../../../profiles/ffmpeg.json#L948)
3. **Should a word shown in the menu be searchable?** In that same category, `bits/s` currently matches both bitrate options. Neither `bps` nor `bits per second` matches either one. The proposed note introduces both terms while P1 asks for exact search parity. The smallest edit is to use the existing searchable spelling in the note. If `bps` is preferred, specify an additive match for qualifying options, preserve existing matches and order, and test that a buffer size never acquires the rate synonym. [Substring matching](../../../cli_help/ui.py#L87)
