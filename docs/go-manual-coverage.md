## Details and insertion boundaries

Build, run and test distinguish the number of simultaneous Go tool processes or package binaries (`-p`) from the limit inside each test binary (`-parallel`). The build-mode row names the output kinds. Coverage rows distinguish statement hits from execution counts, the effect of `-race` on counter selection, and the different default instrumentation scopes for program builds and tests. Overlay Details explain the difference between compile-time replacement files and ordinary filesystem reads by the program. [Build and coverage flags](https://github.com/golang/go/blob/go1.27.4/src/cmd/go/internal/work/build.go)

List syntax depends on the flag. `-tags` and `-coverpkg` take comma-separated entries. `-cpu` takes positive decimal GOMAXPROCS values. `-vet` accepts analyzer names or the special selections `off` and `all`. Assembler, compiler and linker flag lists use shell quoting and optional package patterns. Wrapper commands take a program and fixed arguments in one shell word. Selection of `-buildvcs=` places the cursor after the equals sign for `auto`, `true` or `false`. The bare flag selects true. [Go build flags and parsers](https://github.com/golang/go/blob/go1.26.0/src/cmd/go/internal/work/build.go) · [Test flag parser](https://github.com/golang/go/blob/go1.26.0/src/cmd/go/internal/test/testflag.go)

Benchmark and fuzz budgets accept Go durations or decimal iteration counts such as `100x`. Benchmark time defaults to one second, fuzzing continues indefinitely by default, and minimization defaults to 60 seconds per attempt. Zero disables minimization. Blocking samples measure nanoseconds spent blocked. Allocation samples measure bytes allocated. Mutex sampling selects roughly one in N contention events. The timeout, repetition count, seed and profiling rows describe their individual zero or signed-value behavior. [Duration and iteration parser](https://github.com/golang/go/blob/go1.26.0/src/testing/benchmark.go) · [Fuzzing defaults](https://github.com/golang/go/blob/go1.26.0/src/testing/fuzz.go) · [Testing initialization](https://github.com/golang/go/blob/go1.26.0/src/testing/testing.go) · [Runtime profiling](https://github.com/golang/go/blob/go1.26.0/src/runtime/mprof.go)

Test flags can follow an explicit package list. Both `-args` and `--args` terminate parent-flag insertion and forward the remaining words unchanged. The browser also honors its general `--` boundary. Run flags precede the main package or source files. An argument after that boundary belongs to the program. A version-qualified package runs independently of the current module. [Go command reference](https://pkg.go.dev/cmd/go@go1.27.4) · [Invocation boundaries](invocation-and-structured-arguments.md#keywords-joined-selectors-and-value-groups)

## Verification

The independent regression compares exact menu membership, argument arity, release availability, shared-flag registration and all 29 binary aliases. It checks the older source captures, the structured value contracts, a quoted list before a partial test flag, equals insertion, and forwarding boundaries. [Go menu regressions](../tests/test_go_manual_coverage.py) · [Compatibility and terminal results](devtools-batch-verification.md#compatibility-results)

Fresh executable checks used the checksum-verified Go 1.22.12 and Go 1.26.0 archives from the first audit on the local linux/amd64 host. Each toolchain used a disposable module, private caches, two Go processors and disabled proxy, checksum-server and automatic toolchain downloads. These checks exercised the real Go programs separately from browsing the four menus. [Archive provenance](go-option-audit.md#executable-checks)

| Executable check | Observed result |
| --- | --- |
| Build inputs and parallelism | Initial `-C .`, `-p 0x2`, atomic coverage, a comma-separated package pattern list, overlay and explicit PGO selection produced an executable. A late `-C`, zero parallelism and obsolete `-i` failed. |
| Run boundary | The program received the literal arguments `-cover` and `日本` after its package. Go 1.26.0 accepted `-json` for both build and run. Go 1.22.12 rejected it. |
| Test selection and lists | An iteration-limited benchmark accepted `-test.bench`, `-test.benchtime 1x`, two CPU settings, a negative shuffle seed, disabled vet and per-binary parallelism. A zero CPU setting and an empty internal analyzer-list element failed. |
| Fuzzing and forwarding | The target completed a `1x` run with minimization disabled by `0x`. A fuzzing budget of `0x` failed. Both forwarding markers preserved `-test.list Name`. The Go 1.26.0 client accepted `-artifacts`. Go 1.22.12 rejected it. |
| Tidy | Tidy accepted an initial directory, a separate module file, writable module-cache entries and a source overlay together. The alternate and original module files retained their separate module names. |
