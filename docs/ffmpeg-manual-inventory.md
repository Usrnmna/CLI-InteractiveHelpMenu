# FFmpeg command-line inventory

The starting menu contained 16 rows in two categories. This inventory covers the `ffmpeg` executable. A file operand closes a group of options. An input group ends at `-i URL`, and an output group ends at the output URL. This grouping is significant even when the same spelling works on both sides. [Upstream command syntax and file order](https://ffmpeg.org/ffmpeg.html#Description)

## Selectable inventory

The finished profile contains 1,759 selectable rows in 42 categories, an increase of 1,743 from the original 16. The original spellings retain their order. The table counts each literal once, including spellings with several meanings in different components or releases.

| Source of selectable spelling | Rows | Reconciliation |
| --- | ---: | --- |
| Native CLI | 250 | 237 distinct effect identifiers across these spellings, including historical stream-qualified insertions. The ledger also records one search-only alias, two compatibility no-ops, one unregistered spelling and one parser separator. |
| Library options from three baseline builds | 1,253 | 1,255 effective direct spellings. Two already have native rows in other releases. |
| Additional codec registrations | 163 | 184 candidate names across tagged sources. The remaining 21 have API, read-only or nested uses. |
| Additional format registrations | 19 | Tracker, DASH, WHIP and script-input settings. Six existing rows gain other format owners. |
| Additional device registrations | 53 | Twelve existing rows also gain device-specific Details. |
| Additional protocol registrations | 21 | Of 240 reviewed names, 173 already have a row and 46 have a documented exclusion. |

For library options, an effect depends on the component. The three baseline builds have 38 pairs of direct spellings that share a field on at least one owner. Of these, 25 share all observed owners wherever both occur. Counting each of the remaining pairs as a single effect would conceal a difference between components. The [library option analysis](ffmpeg-avoptions.md) explains the counting method, aliases and exclusions.

## CLI options

The [tab-separated native option inventory](../tests/fixtures/ffmpeg/cli-options.tsv) records a spelling, its effect, operand arity, option scope, release availability, manual-heading evidence and menu disposition. N, R and U denote Noble, Resolute and the named upstream release. M denotes the rolling manual. A missing heading alone does not establish rejection. Scope changes between releases appear in the scope column. The option Details supply the operand syntax.

The question-mark spelling is a help alias. Its punctuation requires shell quoting in contexts where it could match a filename. It is searchable under `-h`. The `--` token in the tagged parser protects the next token as an output URL. It is parser syntax outside the option list. The project editor treats `--` as an editing boundary. For a multi-output edit after a dash-leading local filename, spelling the path as `./-name` avoids that boundary. [6.1.1 parser](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n6.1.1/fftools/cmdutils.c) · [9.1 parser](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/fftools/cmdutils.c)

The Noble manual lists `-sbsf`. The Noble option table registers the audio and video shortcuts only. Use `-bsf:s` with the bitstream-filter chain as a separate argument. The older declarations for `-adrift_threshold` and `-qphist` are compatibility no-ops. They have no selectable effect. [Noble manual](https://manpages.ubuntu.com/manpages/noble/man1/ffmpeg.1.html) · [Noble option table](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n6.1.1/fftools/ffmpeg_opt.c)

## Build-dependent options

A name in full help can belong to a codec, a muxer, a demuxer, a protocol, a scaler, a resampler, a filter or a bitstream filter. The first step in identifying a command-line option is to check native option lookup. The fallback parser looks up library options by name. It can route a single spelling to both codec and format dictionaries. The selected implementation and the file group then determine which settings take effect. Named constants indented below an option are possible operands. Filter parameter names belong inside a filtergraph, and bitstream-filter parameters belong inside the chain passed to `-bsf`. An identically spelled direct option can have a different meaning. [FFmpeg AVOptions](https://ffmpeg.org/ffmpeg.html#AVOptions) · [8.0.1 fallback parser](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n8.0.1/fftools/cmdutils.c)

The codec, format and filter names in help depend on build configuration. Stream specifiers, filter pads, option values read from files and legacy codec prefixes are syntax families. Enumerating every combination would mix user input with literal option spellings. A concrete spelling such as `-c:a:0` remains useful because it demonstrates a type-relative index while preserving the original insertion. [Upstream options and stream specifiers](https://ffmpeg.org/ffmpeg.html#Options)

The [fixed captures](../tests/fixtures/ffmpeg/help/manifest.json) retain short, long and full help as well as the complete version and configure output. Noble reports 87 native option headings in short help and 193 in long help. Resolute reports 41 and 196. The upstream build reports 44 and 194. The input-group opener `-i` occurs in the usage line. A row does not need an option heading in short help to be usable. The historical [format specimen](../tests/fixtures/help/ffmpeg.txt) is the original compact, hand-authored example used by the [discovery matrix](../tests/fixtures/help/matrix.json). It remains separate from the executable captures.

The [library inventory](../tests/fixtures/ffmpeg/avoptions.tsv) records the disposition of each full-help name on each build, its direct operand types and relationships between alias spellings. The native CLI takes precedence where the same name occurs in both layers. For example, `-apply_cropping` is a library option on Noble and a native CLI option on Resolute and 9.1. The reverse transition occurs with `-top`. The six scaler dimensions and formats rejected by the fallback parser are recorded explicitly. Use the native size or pixel-format options as appropriate. The versioned captures contain the full component-specific constants, ranges, defaults and descriptions. [8.0.1 parser](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n8.0.1/fftools/cmdutils.c) · [Capture and build details](../tests/fixtures/ffmpeg/help/README.md)

## Options outside the three fixed builds

The [format supplement](../tests/fixtures/ffmpeg/format-options.tsv) reconciles headings outside the primary inventory with the private format classes in the three source releases. The additional output rows cover WHIP. Input rows cover DASH decryption keys, libmodplug tracker playback, the VapourSynth script-size limit and AviSynth+ frame properties. The same table identifies concat script directives, format names, metadata keys and tee per-output arguments. These belong in the corresponding file or option operand. The MPEG-TS transport ID and detected packet size are exported fields. The internal `skip_changes` and `skip_clear` fields have zero flags and fail the command-line fallback lookup. [Demuxer manual source](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/demuxers.texi) · [Muxer manual source](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/muxers.texi) · [MPEG-TS declarations](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/mpegts.c)

A supplemental 9.1 binary with libmodplug, libxml2 and WHIP recognized all 17 new tracker, DASH and WHIP spellings in debug-mode argument parsing. A separate 9.1 build with the VapourSynth demuxer recognized `-max_script_size 1048576` and exited on `-version`. It used the 9.1 release source, `--disable-everything --enable-ffmpeg --enable-demuxer=vapoursynth --enable-vapoursynth` and the VapourSynth R70 public headers. No script was evaluated. AviSynth+ option availability follows the tagged demuxer declarations. [Tracker option declarations](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/libmodplug.c) · [WHIP muxer](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/whip.c) · [DASH demuxer](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/dashdec.c) · [VapourSynth demuxer](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/vapoursynth.c) · [VapourSynth R70 headers](https://raw.githubusercontent.com/vapoursynth/vapoursynth/R70/include/VSScript4.h) · [AviSynth demuxer](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/libavformat/avisynth.c)

The [device inventory](../tests/fixtures/ffmpeg/device-options.tsv) groups options by spelling, component, direction and source tag. It reconciles 176 distinct device option headings and 181 combinations of spelling, device and direction. Build-specific Details cover Windows DirectShow and GDI, Apple AVFoundation, Android capture, DeckLink and other device APIs. For example, the private x11grab offset name `y` collides with the native `-y` overwrite switch. Use `-grab_y` to specify the capture offset. No device access was needed to verify those registrations. [Input devices](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/indevs.texi) · [Output devices](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/outdevs.texi)

The [conditional codec inventory](../tests/fixtures/ffmpeg/av-codec-source.tsv) identifies option registrations and their owning source files for encoders and decoders available in other builds. A selected row for a hardware or external-library component is qualified by that dependency. Registration establishes spelling and operand handling. Executing an encode on that hardware requires an applicable device and build. [Encoder manual](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/encoders.texi) · [Decoder manual](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/decoders.texi)

The [protocol inventory](../tests/fixtures/ffmpeg/protocol-options.tsv) records direct option names, aliases, URL query parameters, nested values and API exports. An optional upstream build recognized 16 of the 21 added spellings in offline parser checks. Source registrations establish five more under Windows, mbedTLS or librtmp. In both Ubuntu releases, `rtcpport` is a URL query spelling. In 9.1 it is also a direct alias. For `-connect_timeout`, SRT uses milliseconds and the optional libcurl backend uses seconds. For `-key`, the crypto protocol takes hexadecimal data while 9.1 TLS accepts a path to the private-key file. The protocol and format inventories together account for all 33 additional directly routed names found in the companion build's full help. [Tagged protocol manual](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.1/doc/protocols.texi) · [Companion build and captures](../tests/fixtures/ffmpeg/help/README.md#optional-upstream-components)

The listed source releases and four fixed build configurations bound the inventory. Installed codecs, external SDKs, hardware, devices, and supported protocols vary by build. Use `ffmpeg -h full` or component help on the machine that will run the command to check local availability.
