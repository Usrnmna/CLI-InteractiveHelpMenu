## systemctl applicability

- **list-units** now covers recursive enumeration of local containers (requires root), the explicit legend boolean, remote and capsule selection, and dependency expansion. Pass explicit unit names to expand their dependencies. The implementation queries those dependencies before listing the resulting names. `--reverse` adds dependents, `--after` adds units ordered earlier and `--before` adds units ordered later. These switches select the relationship used with `--with-dependencies`. [Unit listing](https://github.com/systemd/systemd/blob/v259/src/systemctl/systemctl-list-units.c) · [Dependency property mappings](https://github.com/systemd/systemd/blob/v259/src/systemctl/systemctl-util.c)
- **show** adds `-P NAME`, which requests a property and prints just its value. Naming a property also includes an empty result if the property exists. A positional numeric operand is a job ID. With a named unit, `--with-dependencies` also works here even though the manual's list of verbs omits show. The show and status paths share name expansion and dependency collection. [Property parser](https://github.com/systemd/systemd/blob/v259/src/systemctl/systemctl.c) · [Show and status implementation](https://github.com/systemd/systemd/blob/v259/src/systemctl/systemctl-show.c)
- **status** adds dependency direction and timestamp formatting. A numeric operand selects the unit containing a process with that PID. `--timestamp=` changes displayed status times. `--output=` changes the recent journal excerpt, which can be suppressed with `--lines=0`. Machine-readable properties remain in show. [Show and status implementation](https://github.com/systemd/systemd/blob/v259/src/systemctl/systemctl-show.c)
- **Shared spellings** include manager selection over SSH, local container selection and, from 256, capsule selection. A capsule connects to its user manager. `--failed` adds the failed state to enumeration. Show and status still look up an explicit literal unit name directly. `--quiet` leaves unit rows and properties available. An explicit legend setting controls the list table. `--no-legend` is accepted on both Ubuntu clients alongside documented `--legend=no`. [255 parser](https://github.com/systemd/systemd/blob/v255/src/systemctl/systemctl.c) · [259 parser](https://github.com/systemd/systemd/blob/v259/src/systemctl/systemctl.c)
- **Original no-effect controls** retain their limitations in Details. The lines setting has no journal excerpt to limit in list-units or show. Plain mode and the legend controls do not convert property or status output into a table. Journal output formats do not reformat properties. The JSON family does serialize the unit table. [First-pass source and fixture comparisons](systemd-option-audit.md)

Of the 88 distinct systemctl parser spellings, 43 appear in at least one of the three query menus. The other 45 control jobs, shutdown, signals, mounts, unit-file changes, editing, cleanup or socket listings. The ledger identifies each exclusion. For example, `--show-types` is for list-sockets, `--show-transaction` describes a queued job, `--global` targets user unit-file operations and `--root=` does not retarget these runtime queries. Legacy `--ignore-dependencies`, `--irreversible` and `--ignore-inhibitors` affect other operations. `--marked` is still accepted by upstream despite its absence from the 262 option headings. Upstream's new `--kernel-cmdline=` and `--kernel-cmdline-reuse` apply to kexec. The `-.` parser branch deliberately returns an error and suggests `--` before a unit name that begins with a dash. All four profiles include the working 262-only `--introspect-cli` action, which emits the executable's CLI schema. [Tagged parser](https://github.com/systemd/systemd/blob/v262/src/systemctl/systemctl.c) · [Upstream CLI introspection tests](https://github.com/systemd/systemd/blob/v262/test/units/TEST-74-AUX-UTILS.introspect-cli.sh)

## journalctl coverage

- **Sources and filters.** The menu covers source selection, namespace sets, exact and after-cursors, checkpoint files, units, invocations, identifiers, facilities, priority, message regular expressions and boot constraints. A cursor file resumes *after* the saved record and is updated to the last record read. The `-I` shortcut consumes no argument and means the most recent invocation. The long option requires a descriptor. `--invocation=all` clears an earlier invocation filter. [259 parser](https://github.com/systemd/systemd/blob/v259/src/journal/journalctl.c) · [Filter implementation](https://github.com/systemd/systemd/blob/v259/src/journal/journalctl-filter.c)
- **Display and actions.** The menu includes field names and distinct field values, all output modifiers, paging, catalogs, boot and invocation lists, integrity checking, storage management and sealing. Vacuum limits delete the oldest archived files. Active files count toward disk usage and can be rotated before vacuuming. Zero disables the respective limit. Size uses bytes or binary suffixes. Bare durations are seconds. The sealing interval must be positive and defaults to 15 minutes. Sealing operations require a build with that support. [Ubuntu journal manual](https://manpages.ubuntu.com/manpages/resolute/man1/journalctl.1.html) · [Size parser](https://github.com/systemd/systemd/blob/v262/src/basic/parse-util.c) · [Time parser](https://github.com/systemd/systemd/blob/v262/src/basic/time-util.c)
- **Release boundaries.** Noble lacks the short file and no-hostname spellings (`-i`, `-W`), while both long options work there. It also lacks identifier exclusion, invocation selection and listing, namespace listing and synchronization on follow exit. Both Ubuntu parsers accept the deprecated current-boot and ID generation switches. The installed Resolute help advertises `--list-namespaces` even though its manual omits an option heading. Upstream 262 also implements it. `-l` and `--full` undo `--no-full` and remain accepted despite being absent from fixed help. [Noble parser](https://github.com/systemd/systemd/blob/v255/src/journal/journalctl.c) · [Resolute parser](https://github.com/systemd/systemd/blob/v259/src/journal/journalctl.c) · [Upstream parser](https://github.com/systemd/systemd/blob/v262/src/journal/journalctl.c)
- **Positional syntax.** The 100 journalctl spellings account for every reviewed option. Journal field matches, standalone `+` disjunctions, absolute path matches, optional catalog message IDs and systemctl unit patterns, job IDs and PIDs are positional operands. They remain outside the selectable option inventories. Environment variables, output-mode names and journal field names are separate manual subjects. [Upstream journalctl synopsis](https://www.freedesktop.org/software/systemd/man/262/journalctl.html)

## Verification

The [offline inventory tests](../tests/test_systemd_manual_inventory.py) compare menu arity and insertable spellings to the ledgers and compare both complete fixed-help declaration sets to the ledger's per-package flags. The initial host run passed 3 tests with 0 failures and 0 skips.

Both packaged clients ran in the Ubuntu 26.04.1 offline host sandbox with Python 3.14.4. A three-record journal imported into a disposable directory allowed a [separate native probe](../tests/fixtures/systemd/probe_clients.py) to confirm identifier matches, regex matching, optional counts, cursor-file resumption without duplication, consistency checking and early rejection of malformed vacuum/interval values. Resolute selected the latest and previous invocations and cleared an earlier invocation filter with `all`. Resolute omitted an excluded identifier from short output while cat and JSON still printed it. Noble rejected the new spellings. Both rejected the upstream-only CLI introspection switch. Maintenance options were parsed with a trailing version action. No journal maintenance request was sent to a running daemon.

A private D-Bus service answered both systemctl clients for three synthetic units. `list-units --with-dependencies --reverse` included a dependent service, `show --with-dependencies -PId` included the named service and its wanted timer, and `status --with-dependencies --after --lines=0` included the earlier-ordered timer. Quiet list output matched `--legend=no` and an explicit yes restored the column headings. These observations concern the Ubuntu implementations. Upstream 262 behavior is based on its manual and tagged source.
